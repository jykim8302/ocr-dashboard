# 마우스 움직임 따라하기 (Mouse Tracer)

마우스가 움직인 길을 **그대로** 기록했다가, 똑같은 속도로 **실제로 움직이며** 다시 재생하는 프로그램입니다.
좌표로 순간이동시키지 않고, 기록된 시간 간격대로 한 칸씩 밀어주기 때문에 사람이 직접 움직이는 것과 같은 궤적이 나옵니다.

## 실행 방법

`MouseTracer.bat` 을 **더블클릭**하면 끝입니다.
처음 실행하면 같은 폴더에 `mouse_tracer.py` 가 자동으로 만들어지고 창이 뜹니다.

- Windows 전용입니다.
- Python 3 가 필요합니다. 없으면 자동 설치를 물어봅니다.
- 별도의 라이브러리 설치는 필요 없습니다. 파이썬 기본 기능만 씁니다.

## 단축키

처음 값은 아래와 같습니다. 창이 뒤에 있어도 그대로 동작합니다.

| 키 | 기능 |
|----|------|
| F6 | 녹화 시작 / 중지 |
| F7 | 재생 시작 / 중지 |
| F8 | 전부 정지 |

창의 **단축키** 칸에서 바꿀 수 있습니다. 기능마다 키를 고르고 Ctrl, Alt, Shift 를 함께 누르게 할 수 있습니다. **단축키 적용** 을 누르면 바로 바뀌고 저장됩니다.

F1 부터 F12, 숫자패드, Insert, Home, PageUp 같은 키를 고를 수 있습니다. 다른 프로그램이 이미 쓰는 키는 등록에 실패하고 로그에 어떤 것이 실패했는지 나옵니다. 그때는 다른 키로 바꾸면 됩니다.

바뀐 단축키는 녹화에서 자동으로 빠지므로, 단축키를 누른 것이 기록에 섞이지 않습니다.

## 설정

- **반복 횟수** : 0 을 넣으면 정지할 때까지 무한 반복합니다.
- **재생 속도** : 1.0 이 녹화한 그대로입니다. 2.0 이면 두 배 빠르게 재생합니다.
- **키보드 입력도 함께 기록** : 마우스뿐 아니라 키보드도 같이 따라 합니다.
- **재생 전 시작 위치로 커서 이동** : 녹화를 시작했던 지점부터 다시 그립니다.
- **정밀 모드** : 재생하는 동안만 마우스 가속을 꺼서 궤적을 정확히 재현합니다. 재생이 끝나거나 프로그램을 닫으면 원래 설정으로 자동 복구됩니다.

기록은 `파일로 저장` 으로 저장해 두었다가 `파일 불러오기` 로 다시 쓸 수 있습니다.

## 설정 기억하기

반복 횟수, 재생 속도, 쉬는 시간, 체크박스, 피코 포트, 단축키를 창을 닫을 때 저장했다가 다음에 켜면 그대로 불러옵니다.

`mouse_tracer_settings.json` 파일에 저장됩니다. 프로그램과 같은 폴더에 생깁니다. 처음 상태로 되돌리고 싶으면 이 파일을 지우면 됩니다.

## Raw Input 방식

녹화는 전부 Win32 **Raw Input** 으로 합니다. 커서 좌표를 반복해서 읽어보는 방식이 아닙니다.

- 숨은 창을 하나 만들고 `RegisterRawInputDevices` 로 마우스(usage 0x01/0x02)와 키보드(0x01/0x06)를 `RIDEV_INPUTSINK` 로 등록합니다. 창이 뒤에 있어도 원시 입력이 계속 들어옵니다.
- 입력은 `WM_INPUT` 메시지로 도착하고, `GetRawInputBuffer` 로 쌓인 패킷을 한 번에 모두 긁어옵니다. 1000Hz 같은 고속 마우스에서도 패킷을 흘리지 않습니다. 버퍼가 비어 있으면 `GetRawInputData` 로 한 건씩 읽습니다.
- 기록하는 값은 장치가 보고한 **원시 이동량 그 자체**(`RAWMOUSE.lLastX`, `lLastY`)입니다. 화면 픽셀이 아니라 마우스 센서가 센 카운트라서, 화면 경계에 닿아도 값이 잘리지 않고 미세한 떨림까지 그대로 남습니다.
- 버튼과 휠은 `usButtonFlags` 와 `usButtonData`, 키보드는 `MakeCode` 스캔코드로 기록합니다.
- 태블릿처럼 절대 좌표를 보고하는 장치는 `usFlags` 의 `MOUSE_MOVE_ABSOLUTE` 를 같이 저장해 재생 때 같은 방식으로 돌려줍니다.
- 창에 초당 패킷 수와 마지막 원시 이동량, 인식된 장치 이름이 실시간으로 표시되니 raw input 이 잘 들어오는지 바로 확인할 수 있습니다.

재생은 `SendInput` 의 **상대 이동**(`MOUSEEVENTF_MOVE | MOUSEEVENTF_MOVE_NOCOALESCE`) 으로 합니다. 기록된 시각마다 같은 크기의 원시 이동량을 그대로 넣어주므로 커서가 실제로 그 경로를 따라 흘러갑니다. 좌표를 지정해 순간이동시키지 않습니다. 사용자 모드에서 입력을 만들어 넣는 방법은 `SendInput` 뿐이라 이 부분은 raw input 이 아니라 합성 입력입니다.

- 재생하며 만든 입력에는 표식(`dwExtraInfo`)을 달아두어, 녹화 중이더라도 자기 입력을 다시 기록하지 않습니다.
- 재생을 중간에 멈추면 아직 눌린 채인 버튼과 키를 자동으로 놓아줍니다.

## 재생을 raw input 으로 받게 하려면

`SendInput` 으로 만든 입력도 Windows 의 Raw Input 스트림에 그대로 나타납니다. `WM_INPUT` 을 읽는 프로그램은 이 입력을 받습니다. 다만 `RAWINPUTHEADER.hDevice` 값이 0 으로 들어옵니다. 진짜 마우스에서 온 입력은 0 이 아닌 장치 핸들을 가집니다.

창의 **재생 입력이 Raw Input 으로 잡히는지 검사** 버튼을 누르면 직접 확인할 수 있습니다. 커서가 제자리로 돌아오도록 좌우로만 조금 움직이면서, 보낸 입력이 `WM_INPUT` 으로 되돌아오는지와 그때의 `hDevice` 값을 로그에 적어 줍니다.

- 대상 프로그램이 Raw Input 을 그냥 읽기만 한다면 지금 이대로 동작합니다.
- 대상 프로그램이 `hDevice` 가 0 인 입력을 걸러낸다면 사용자 모드에서는 방법이 없습니다. 실제 USB HID 장치가 필요합니다. 라즈베리파이 피코나 아두이노(ATmega32U4 계열)를 USB 마우스로 동작시키고, 이 프로그램이 기록한 원시 이동량을 그쪽으로 보내 대신 움직이게 하는 방식입니다. 이러면 운영체제가 보기에 진짜 마우스라서 `hDevice` 도 정상적으로 붙습니다.

## 재생이 안 들어갈 때

맨 앞에 있는 창이 관리자 권한으로 돌고 있으면 일반 권한 프로그램은 그 창에 입력을 넣을 수 없습니다. Windows 가 막습니다. 이때 `SendInput` 은 오류 코드 5 를 돌려줍니다.

- 창 아래쪽 **관리자 권한으로 다시 실행** 버튼을 누르면 같은 프로그램이 관리자로 다시 열립니다.
- 재생 중 입력이 거부되면 프로그램이 알아서 방식을 낮춥니다. 먼저 단순 이동으로 바꾸고, 그래도 계속 막히면 구형 `mouse_event` 경로로 넘어갑니다. 어떤 단계로 바뀌었는지 로그에 남습니다.
- **검사** 버튼은 세 가지 방식을 차례로 시험해 어느 것이 통하는지 알려줍니다. 결과는 **로그 전체 복사** 버튼으로 복사할 수 있습니다.

## 피코로 재생하기 (진짜 USB 마우스)

`SendInput` 으로 만든 입력은 Raw Input 스트림에 안 나타날 수 있습니다. Windows 에는 raw input 을 보내는 함수가 없기 때문입니다. Raw Input 만 읽는 프로그램을 움직이려면 실제 USB 장치가 있어야 합니다.

라즈베리파이 피코를 USB 마우스로 만들어 쓰는 방법입니다. 운영체제가 보기에 진짜 마우스라서 raw input 에 정상으로 잡힙니다.

1. `pico` 폴더의 `설치방법.txt` 대로 피코에 CircuitPython 과 `boot.py`, `code.py` 를 넣습니다.
2. 피코를 PC 에 꽂습니다. 마우스 하나와 COM 포트 하나가 새로 생깁니다.
3. 창에서 **포트 찾기** 를 누르고 새로 생긴 포트를 고릅니다.
4. **피코 사용** 을 켜고 **연결 시험** 을 눌러 커서가 네모를 그리는지 봅니다.
5. 그다음부터 재생하면 움직임이 피코를 거쳐 나갑니다.

PC 와 피코는 5바이트 묶음으로 이야기합니다. 시작 표시, 가로 이동량, 세로 이동량, 눌린 버튼, 휠 순서입니다. 127 을 넘는 이동량은 여러 묶음으로 쪼개 보냅니다. 시리얼 통신도 Windows API 를 직접 부르기 때문에 따로 설치할 것은 없습니다.

키보드는 피코 경로로 보내지 않습니다. 피코가 마우스로만 동작하기 때문입니다.

## 점검 스크립트

Windows 전용이라 리눅스에서는 실행할 수 없습니다. 대신 Win32 함수를 가짜로 바꿔치고 모듈을 불러들여, 실행 없이 확인할 수 있는 것을 모두 봅니다.

```
python3 tests/check.py
```

구조체 크기와 필드 위치, 원시 입력에서 진짜 장치와 만들어낸 입력 구분, 재생 시 버튼과 휠과 키보드 처리, 안 뗀 버튼 자동 해제, 피코 경로의 총 이동량 보존과 클릭 위치, 단축키 등록, 설정과 기록 파일 왕복, 그리고 한 번 고친 버그가 되살아나지 않는지를 봅니다. 모두 82개 항목이고, 한 항목이라도 실패하면 종료 코드 1 을 돌려줍니다.

피코 펌웨어는 흉내 내지 않고 `pico/code.py` 를 그대로 불러들여 돌립니다. `usb_cdc`, `usb_hid`, `adafruit_hid` 를 가짜로 끼우고 실제 프레임을 먹인 뒤 무엇을 냈는지 봅니다. 펌웨어를 망가뜨리면 검사가 실패하는 것도 확인했습니다.

## 프로그램 파일을 고쳤다면

실행 파일은 켤 때마다 같은 폴더의 `mouse_tracer.py` 를 자기가 품고 있는 내용으로 다시 씁니다. 직접 고친 내용이 있으면 덮어쓰기 전에 `mouse_tracer.py.bak` 로 남겨 두고 알려 줍니다.

- 게임의 안티치트나 보안 프로그램은 합성 입력을 차단하거나 제재할 수 있습니다. 허용된 곳에서만 쓰세요.
- 무한 반복 재생 중에는 F8 로 언제든 멈출 수 있습니다.
